# 项目维护约定

- 项目自行维护的代码、样式、模板、配置和测试说明注释统一使用简洁、准确的中文；必要的技术名词、标识符、配置指令、代码示例和第三方许可证声明保留原文。
- 本目录是实际前端开发目录；后端及前端 subtree 镜像位于 `D:/IDEA_project/nebula-blog`。不直接修改镜像中的前端文件。
- 问题记录只维护后端根目录的两份文档：`D:/IDEA_project/nebula-blog/ISSUES.md` 记录待处理、待确认和待验证事项，`D:/IDEA_project/nebula-blog/FIXES.md` 只记录已完成的问题修复。
- 功能补全、界面优化和维护整理统一写入 `D:/IDEA_project/nebula-blog/更新日志.md`，不放在 `FIXES.md` 中。新增功能自身的使用规则随功能记录，已有功能的错误修复按问题记录处理。
- 三份记录都按 `## YYYY-MM-DD` 分区，同日追加，新日期放在前面。问题说明写清发生条件、原因、后果、当前依据和处理方向，尽量不用生僻术语；未经验证的内容明确标注。
- 修复并验证后，将条目从 `ISSUES.md` 移入 `FIXES.md`，简要说明问题和修复结果，不重复保留已关闭记录。更新日志简要说明新增能力或改进结果。
- 早期开发留下的临时、试验性单元测试及其运行差异不归入 `ISSUES.md` 或 `FIXES.md`；相关整理记入 `更新日志.md`。正式回归测试发现的实际业务缺陷仍按问题记录处理。
- 不在本目录或其他目录新建问题、审查、修复、验收总结文档。环境、使用及 Git 文档只保留自己的用途和上述记录的入口；原始日志、截图不另扩展为第三份问题记录。
- 用户要求提交时按后端 `git-subtree-guide.md` 先将前端子树合到后端，再提交后端；未要求时不擅自提交或同步子树。
- 任务结束默认关闭项目前后端服务；不操作 Windows 服务，也不随之关闭 MySQL、Redis 或 Docker。
